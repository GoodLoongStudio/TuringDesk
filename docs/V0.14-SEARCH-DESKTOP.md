# TuringDesk v0.14 — Search Desktop Execution Plan

## Product decision

TuringDesk no longer uses the old Home dashboard or the bottom-right AI Orb as primary product surfaces.

The default desktop experience is:

1. Wallpaper/scene desktop engine behind Explorer icons.
2. A persistent AI search/conversation bar near the top-center of the primary monitor.
3. Desktop icons must not visually collide with the search bar reserved area.
4. A design/settings button on the search bar opens one integrated settings center.
5. Desktop Library is the source of truth for imported desktop scenes/themes.
6. DeepSeek Harness runs in the background and is hidden behind beginner-friendly model settings.

## Default desktop UX

### Search bar
- Position: horizontally centered, upper area of primary monitor.
- Always visible while TuringDesk enhancement mode is active.
- Input accepts natural language.
- Enter submits directly to TuringDesk Runtime / DeepSeek Harness-backed agent flow.
- The result uses lightweight native conversation/trace cards; no old Home page is required.
- Optional microphone action uses the existing Windows speech service.
- Design/settings icon opens the integrated desktop settings center.
- Alt+Space focuses the search bar instead of opening an Orb.

### Desktop icon exclusion zone
- Reserve a padded rectangle around the search bar.
- In TuringDesk-owned desktop surfaces, icon layout must skip that rectangle.
- In Explorer enhancement mode, TuringDesk should best-effort relocate desktop icons that overlap the reserved rectangle without replacing Explorer.
- Failure to relocate Explorer icons must never break Explorer or hide the Windows desktop.

### Integrated settings
The search bar design/settings button opens a single settings window containing:
- Desktop Library / scene import
- scene properties/editor entry
- playlists
- multi-monitor profiles
- application rules
- performance / fullscreen behavior
- AI provider / model / API key
- DeepSeek Harness advanced console entry
- diagnostics / advanced shell options

## Removed product surfaces

The following are removed from the normal user flow:
- AgentOrbWindow
- old MainWindow Home/Apps/Workspace/Tasks/Memory dashboard
- old Home dashboard launch buttons

MainWindow may remain as an internal service owner/controller temporarily, but it must stay hidden in default enhancement mode and must not be presented as the product UI.

## Implementation checklist

### P0 — deliverable build
- [ ] Add `DesktopSearchBarWindow`.
- [ ] Center it near the top of the primary monitor.
- [ ] Register Alt+Space to focus/open the search input.
- [ ] Send input through existing `SubmitExternalCommandAsync` flow.
- [ ] Add design/settings button that opens Desktop Library / integrated settings.
- [ ] Remove Orb creation from enhancement mode.
- [ ] Delete AgentOrbWindow source files.
- [ ] Keep MainWindow hidden in default enhancement mode.
- [ ] Add icon exclusion rectangle service shared by desktop surfaces.
- [ ] Make TuringDesk-owned desktop icon layout skip the exclusion zone.
- [ ] Add safe best-effort Explorer icon overlap relocation for enhancement mode.
- [ ] Build Desktop + ShellHost successfully.
- [ ] Build ARM64 MSI successfully.

### P1 — model/Harness unification
- [ ] Saving beginner model settings updates the runtime used by quick AI.
- [ ] Harness background process starts with the same provider/model/key context.
- [ ] Model changes restart/reconfigure Harness when necessary.
- [ ] API key is not written in plaintext to a normal project settings file.

### P2 — integrated settings polish
- [ ] Desktop Library is the default settings entry from search bar.
- [ ] AI settings are available from the same window.
- [ ] Harness WebUI is labeled Advanced and is not required for normal usage.
- [ ] Old Home dashboard is inaccessible from the normal desktop UX.

## Acceptance criteria for test package

A build is testable only when all of the following are true:

1. Launching TuringDesk leaves Explorer/taskbar intact.
2. Applied scenes render on the actual desktop background.
3. No bottom-right Orb appears.
4. A top-center search bar appears on the primary monitor.
5. Clicking the search box and pressing Enter sends an AI request.
6. Alt+Space focuses the same search box.
7. Clicking the design/settings icon opens the integrated desktop settings/Desktop Library.
8. Desktop icons do not overlap the reserved search-bar area in TuringDesk-owned desktop mode; Explorer mode performs safe best-effort avoidance.
9. Old Home dashboard is not shown during normal startup.
10. Desktop/ShellHost compile, runtime smoke tests pass, and the ARM64 MSI validates in CI.

## Release target

Test package name: `TuringDesk-v0.14.0-win-arm64.msi`

This document is the execution contract for v0.14. Do not reintroduce the Orb or old Home dashboard as default UX.
