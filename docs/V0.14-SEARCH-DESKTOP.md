# TuringDesk v0.14 — Search Desktop Execution Plan

## Product decision

TuringDesk no longer uses the old Home dashboard or the bottom-right AI Orb as primary product surfaces.

The default desktop experience is:

1. Wallpaper/scene desktop engine behind Explorer icons.
2. A persistent AI search/conversation bar near the top-center of the primary monitor.
3. The search bar belongs to the desktop Z-order band: above Explorer desktop, below every normal application window.
4. Desktop icons must not visually collide with the search bar reserved area.
5. A design/settings button on the search bar opens one integrated settings center.
6. Desktop Library is the source of truth for imported desktop scenes/themes.
7. DeepSeek Harness is a core background service and begins booting before MainWindow is constructed.
8. Beginner model setup and the official Harness Models page share the same Harness settings/credential stores.

## Default desktop UX

### Search bar
- Position: horizontally centered, upper area of primary monitor.
- Visible on the desktop while TuringDesk enhancement mode is active.
- Never globally always-on-top; ordinary apps, settings windows, browsers and games cover it normally.
- Input accepts natural language.
- Enter submits directly to TuringDesk Runtime / DeepSeek Harness-backed agent flow.
- Optional microphone action uses the existing Windows speech service.
- Design/settings icon opens the integrated desktop settings center.
- Alt+Space focuses the same search bar instead of opening an Orb; after focus it returns to the desktop Z-order band.

### Desktop icon exclusion zone
- Reserve a padded rectangle around the search bar.
- In TuringDesk-owned desktop surfaces, icon layout must skip that rectangle.
- In Explorer enhancement mode, TuringDesk should best-effort relocate desktop icons that overlap the reserved rectangle without replacing Explorer.
- Failure to relocate Explorer icons must never break Explorer or hide the Windows desktop.

### Shared AI configuration
- TuringDesk onboarding and later model settings use one `UnifiedModelConfigurationService` write path.
- Provider/model/base URL are mirrored to the official `$DSH_HOME/settings.yaml` namespaces.
- API credentials are mirrored to the official writable `$DSH_HOME/.credentials.yaml` store used by `dsh-credentials-local` and the Harness Models page.
- TuringDesk must not inject provider API keys into the official Harness WebUI process environment because inherited environment credentials are read-only and shadow the writable credential store.
- Windows Credential Manager remains a migration/fallback copy for TuringDesk, while reads prefer the shared Harness credential store.
- Harness settings and credentials hot-reload; model saves should not require opening the advanced Harness window.

### Integrated settings
The search bar design/settings button opens a single settings window containing:
- Desktop Library / scene import
- scene properties/editor entry
- playlists
- multi-monitor profiles
- application rules
- performance / fullscreen behavior
- AI provider / model / API key
- DeepSeek Harness advanced console entry
- diagnostics / advanced shell options

## Removed product surfaces

The following are removed from the normal user flow:
- AgentOrbWindow
- old MainWindow Home/Apps/Workspace/Tasks/Memory dashboard
- old Home dashboard launch buttons

MainWindow may remain as an internal service owner/controller temporarily, but it must stay hidden in default enhancement mode and must not be presented as the product UI.

## Acceptance criteria for test package

A build is testable only when all of the following are true:

1. Launching TuringDesk leaves Explorer/taskbar intact.
2. Applied scenes render on the actual desktop background.
3. No bottom-right Orb appears.
4. A top-center search bar appears on the primary monitor.
5. Normal application windows render above the search bar.
6. Clicking the search box and pressing Enter sends an AI request.
7. Alt+Space focuses the same search box and it returns to desktop Z-order afterward.
8. Clicking the design/settings icon opens the integrated desktop settings/Desktop Library.
9. Desktop icons avoid the reserved search-bar area best-effort without destabilizing Explorer.
10. Old Home dashboard is not shown during normal startup.
11. Harness begins booting before MainWindow creation.
12. A Key saved in first-run/model settings is stored in the same official Harness credential store used by the Models page.
13. Desktop/ShellHost compile, runtime/Harness smoke tests pass, and the ARM64 MSI validates in CI.

## Release target

Test package name: `TuringDesk-v0.14.2-win-arm64.msi`

This document is the execution contract for v0.14. Do not reintroduce the Orb, old Home dashboard, global always-on-top search, or split beginner/Harness API credential stores as default UX.
