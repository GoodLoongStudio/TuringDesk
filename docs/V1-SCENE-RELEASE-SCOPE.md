# TuringDesk 首个对外版本 Scene 发布范围

> 状态：待评审发布范围  
> 版本：0.1  
> 日期：2026-08-20  
> 设计依据：[TURINGDESK-DESIGN-SPEC.md](./TURINGDESK-DESIGN-SPEC.md)

## 1. 发布决定

首个对外版本采用 **效果优先的 Creator Lite**。

首版的核心承诺不是“我们有一个功能很多的编辑器”，而是：

> 用户安装 TuringDesk 后，可以立即选择至少 3 个明显不同、达到展示品质的酷炫桌面效果，并稳定应用到真实 Windows 桌面；用户还可以对这些场景进行简单个性化，并用基础编辑器组合自己的轻量场景。

首版不承诺完整专业时间轴、完整粒子系统编辑器或用户 Shader 编辑器。

## 2. 为什么采用这个范围

### 2.1 用户价值来自最终桌面效果

普通用户首先判断的是：

- 场景是否真的显示在 Explorer 图标后面；
- 效果是否明显、流畅、好看；
- 点击应用后是否立即生效；
- 重启、全屏游戏和多屏后是否仍然可靠；
- 是否可以调整颜色、强度、动态和交互。

时间轴面板、粒子参数数量或 Shader 节点数量本身不构成用户价值。如果桌面应用失败或内置效果不够吸引人，再完整的编辑器也不能支撑首版发布。

### 2.2 当前实现已经适合 Creator Lite

现有 Scene 运行时已经具备：

- Image、Text、Shape 和 Particle 图层；
- 位置、大小、缩放、旋转和透明度；
- blur 与 glow 效果；
- opacity、x、y、rotation、scale 的简单时间轴；
- 鼠标视差；
- 场景/图层音频响应；
- 用户属性；
- 编辑器与桌面共用真实 Renderer 预览；
- Video、Web 和 Scene 播放路径；
- pause、resume 和 stop 生命周期。

这些能力足以做出几套有吸引力的第一方场景，也足以提供基础创作体验。

### 2.3 完整 Shader 编辑器尚未形成产品能力

当前 GPU 场景是内置 preset 驱动，并不等于用户可以编辑 HLSL/Shader graph。若在首版承诺 Shader 编辑器，还需要额外解决：

- Shader 编译与错误反馈；
- 参数反射和属性绑定；
- GPU 兼容性与驱动差异；
- 资源和纹理输入；
- 沙箱与崩溃隔离；
- 编辑器节点/代码体验；
- 导入包安全；
- 多架构、多显卡测试。

这会显著扩大首版范围，而且不能直接提高“几个酷炫桌面能否应用成功”的确定性。

## 3. 首版必须交付的展示场景

至少交付 3 个第一方展示品质场景。建议目标为 4 个，前三个是发布硬门槛，第四个在稳定后加入。

### 3.1 Aurora Flow——极光流体

视觉目标：柔和但明显的多层极光、颜色漂移、呼吸式光晕和少量景深粒子。

必须体现：

- 多层发光；
- 缓慢循环动画；
- 鼠标轻微视差；
- 强调色、动态强度和动态开关；
- 静止时仍然是可用壁纸，不依赖持续高帧率才好看。

### 3.2 Neon Pulse——霓虹脉冲

视觉目标：赛博霓虹网格、流动光线和高对比粒子，适合展示 TuringDesk 的动态感。

必须体现：

- 霓虹网格和 glow；
- 粒子流动；
- 可选系统音频响应；
- 音频不可用时仍有正常的非音频动画；
- 主色、粒子数量/强度和音频响应开关。

### 3.3 Orbital Calm——深空轨道

视觉目标：有明确层次的星空、轨道、缓慢运动主体和景深粒子，强调沉浸但不干扰桌面图标。

必须体现：

- 前中后景深；
- 粒子与轨道循环；
- 鼠标视差；
- 速度、粒子密度和配色属性；
- 长时间运行无明显跳帧或动画断点。

### 3.4 可选：Liquid Glass / Digital Rain

用于证明 Web 或更丰富 GPU 效果路径。只在前三个场景稳定、发布包大小和资源占用可接受后进入首版。

它不能成为前三个内置场景延期的理由。

## 4. “展示品质”的定义

内置场景必须同时满足：

1. 在设置页有真实预览图或动态预览，不能继续显示空白通用 Scene 卡片。
2. 三个场景第一眼明显不同，不能只是更换背景色。
3. 应用后约 1 秒内真实 Windows 桌面发生可见变化。
4. 场景位于 Explorer 图标后，不遮挡图标、右键菜单、任务栏或普通应用。
5. 退出并重新启动 TuringDesk 后恢复当前场景。
6. 100%、125%、150%、200% DPI 下无明显裁切或错位。
7. 单屏和至少一种双屏配置下可用。
8. 全屏规则触发 pause/stop 后资源使用明显下降，退出全屏后可恢复。
9. 连续运行 2 小时无持续内存增长、WebView/GPU 僵尸或动画时钟泄漏。
10. 每个场景至少有 3 个真正生效的用户属性。

## 5. 首版 Creator Lite 编辑器承诺

### 5.1 必须支持

- 从现有场景复制并编辑；
- 新建基础 Scene；
- 添加图片、文字、Shape 和基础 Particle 图层；
- 图层显示/隐藏、重命名、排序和删除；
- 调整位置、尺寸、缩放、旋转和透明度；
- 鼠标视差及强度；
- blur、glow 等少量稳定效果；
- 为 opacity、x、y、rotation、scale 添加双关键帧循环动画；
- 基础粒子数量、大小、速度、生命周期和颜色；
- 实时预览使用与桌面相同的 Renderer；
- 保存；
- 保存并应用；
- 再次打开后内容不丢失；
- 导入/导出版本化场景包。

### 5.2 用户属性

首版至少支持并实际绑定：

- color；
- slider；
- toggle/bool；
- combo；
- text；
- media/file replacement。

内置场景不要求用户打开编辑器即可调整常用属性。

### 5.3 可以内部使用，但不作为编辑器承诺

第一方场景可以由开发者通过代码、manifest、Web 或受控 GPU preset 使用：

- 更复杂的粒子组合；
- 多条时间轴；
- 音频频段驱动；
- GPU 特效；
- WebGL/Canvas 效果；
- 自定义脚本。

这些能力只对内置场景效果负责，不代表首版必须向普通用户提供完整可视化编辑入口。

## 6. 明确不进入首版的编辑能力

- Shader graph；
- HLSL/GLSL 代码编辑与编译；
- 任意自定义 Shader 导入；
- 专业多轨时间轴、曲线编辑器和关键帧拖拽；
- 粒子发射器节点图、碰撞、流体和 GPU 粒子编辑器；
- 3D 模型材质、灯光、骨骼或摄像机编辑；
- 视频剪辑；
- Web 场景可视化网页编辑器；
- 插件市场和在线创意工坊；
- AI 自动生成完整 Scene 工程。

数据格式可以为未来能力预留字段，但 UI 不得展示无法可靠使用的占位按钮。

## 7. 应用成功是 P0

下列链路必须作为一个整体验收：

```text
设置页选择场景
  -> 点击应用到桌面
  -> 保存当前 SceneId 与属性
  -> 找到 Explorer WorkerW/Progman 宿主
  -> 创建/复用正确显示器的 Scene Renderer
  -> 绘制第一帧
  -> 校验场景窗口可见且位于图标后
  -> 重启后恢复
```

不能把 `SetParent` 成功、`Attached=true`、设置页标题变化或 Renderer 对象创建成功当作最终成功。最终标准是目标 Windows 机器上的真实桌面出现正确画面。

失败时必须记录：

- 选择的 SceneId；
- 场景包和 manifest 路径；
- Explorer host 候选与最终 HWND；
- `SetParent`/Z-order/窗口矩形结果；
- Renderer 类型和第一帧状态；
- 播放错误；
- 回退路径。

## 8. 性能范围

首版不追求所有场景恒定 60 FPS，而追求可控和稳定：

- 默认目标 30 或 60 FPS，由场景声明和全局设置共同限制；
- 静态或低动态场景不得无意义持续刷新；
- pause 停止动画、音频采集、脚本计时和连续 GPU 刷新；
- stop 释放视频、Web 和重型 GPU 资源；
- 内置场景在目标硬件上不应明显影响普通桌面操作；
- 音频响应、粒子密度和高质量效果必须能降级或关闭。

发布测试至少覆盖一台目标 ARM64 设备和一台 x64 设备；若其中一个架构不发布，仍需公开说明未验证状态。

## 9. 首版验收矩阵

| 范围 | 最低验收 |
|---|---|
| 内置场景 | 3 个展示品质、视觉明显不同的场景 |
| 应用 | 约 1 秒内在真实 Explorer 桌面可见 |
| 持久化 | 重启应用后恢复场景与属性 |
| 属性 | 每场景至少 3 个可见且实际生效的属性 |
| 交互 | 至少 1 个场景支持鼠标视差 |
| 音频 | 至少 1 个场景支持可关闭的音频响应 |
| 粒子/时间轴 | 至少 1 个场景证明粒子和循环动画可长期运行 |
| 编辑器 | 基础图层、变换、效果、简单动画、保存与应用 |
| 多屏 | 单屏和双屏至少一种配置通过 |
| 全屏 | pause/stop 和恢复通过 |
| 稳定性 | 2 小时 soak 无明显泄漏或僵尸资源 |
| 回退 | 场景失败不覆盖或破坏 Explorer |

## 10. 发布门槛

以下任一情况存在时，不应对外宣称 Scene/Wallpaper Engine 能力已完成：

- 三个内置场景只是颜色变化或空白占位图；
- 点击应用后真实桌面不变化；
- 只能在编辑器预览中播放，不能在 Explorer 桌面播放；
- 场景重启后丢失；
- 全屏 pause/stop 只是 UI 状态，资源仍持续运行；
- 属性控件存在但不改变场景；
- 多屏或 DPI 变化导致场景覆盖普通应用；
- 必须打开 AI/Harness 才能使用桌面效果；
- 为了声称支持 Shader 而暴露不稳定或无法保存的占位编辑器。

## 11. 后续版本方向

首版稳定后，按用户价值逐步增加：

1. 更完整的关键帧和多轨时间轴；
2. 可视化粒子发射器；
3. GPU effect/shader 参数系统；
4. 受控 Shader graph；
5. 3D 场景；
6. 在线场景分发与社区生态；
7. AI 辅助生成图层、参数和动画。

任何后续编辑器功能都必须继续使用与真实桌面一致的 Renderer，并通过保存、重开、应用和性能测试。

## 12. 固定结论

首个对外版本的 Scene 承诺确定为：

> **至少 3 个展示品质内置场景 + 可靠应用/恢复 + 可调用户属性 + Creator Lite 基础编辑器。**

时间轴和粒子进入首版的方式是“简单、可用、为效果服务”；完整 Shader 编辑器和专业创作工具不属于首版范围。
